Статус: проектирование, 2026-11-09. IPK не создан, SDK не установлен, телевизор не подключался. Минимальная оболочка должна содержать локальный HTML/CSS/JS, шрифты, иконки и экран настройки: при выключенном Raspberry Pi она запускается, показывает настройки, сохранённый адрес сервера и понятное состояние недоступности. Каталог и сетевое воспроизведение при этом не обещаются.

## Решение: packaged оболочка, серверные функции отдельно

| Вариант | Запуск без Pi | Обновление | Риск |
| --- | --- | --- | --- |
| Весь UI внутри IPK | Локальные экраны доступны | Новый IPK для UI | Размер и совместимость JS |
| Hosted UI, переход на URL Pi | Нет гарантии UI | Серверная выкладка | Недоступность Pi даёт пустой экран |
| Локальная оболочка и локальный базовый UI + Config API | Да, настройки и диагностика | IPK для UI; сервер для данных | Нужен контракт версий |

Для MVP выбрать третий вариант. Не использовать безусловный redirect/iframe на Pi и не скачивать исполняемый JS из произвольного URL. Если позднее допускается hosted-режим, оставить локальный аварийный экран, таймаут, возврат в настройки и явную версию контракта. Переключение режима не должно стирать сохранённый адрес или локальные настройки. Локальная оболочка не означает offline-каталог.

Предлагаемое содержимое IPK: `appinfo.json`, `index.html`, локальные `assets/`, лицензии, обработчик пульта, экран ввода адреса и небольшой клиент Config API. Все пути относительные. До сборки проверить внешние script/font/image URL в upstream и решить каждый отдельно. Хранение минимальных настроек на TV допустимо; секрет администратора и ключи внешних сервисов там не хранить.

Пример метаданных для будущей сверки со схемой SDK:

```json
{
  "id": "org.example.lampa.local",
  "version": "0.1.0",
  "vendor": "Local project",
  "type": "web",
  "main": "index.html",
  "title": "Lampa Local",
  "icon": "icon.png"
}
```

ID, иконки, разрешение, обязательные поля и параметры Back нужно подтвердить по текущему appinfo guide. Это эскиз, не валидированный манифест.

## Сборка, установка и обновление: будущая процедура

Ожидаемая цепочка CLI ниже — документируемый ориентир; команды не запускались, синтаксис необходимо сверить с установленной версией webOS TV CLI:

```sh
ares-package ./webos-app
ares-setup-device
ares-novacom --device livingroom --getkey
ares-install --device livingroom ./org.example.lampa.local_0.1.0_all.ipk
ares-launch --device livingroom org.example.lampa.local
ares-inspect --device livingroom --app org.example.lampa.local
```

На TV предполагается официальный Developer Mode с LG developer account, включением режима и Key Server, затем настройкой устройства на рабочей машине. Точные сроки сессии, условия продления, удаление приложений при истечении и ограничения количества/размера требуют чтения актуальной документации и проверки TV. Developer Mode не считать постоянным каналом доставки для пользователя. Публикация через LG Content Store — отдельная процедура проверки и регистрации, в этот проект не входит; обход ограничений Developer Mode не проектируется.

Обновление оболочки: тот же app ID, повышенная версия, резервная копия настроек, установка нового IPK и проверка сохранности local storage на конкретном TV. Не предполагать сохранность данных после удаления приложения. Хранить предыдущий IPK, но downgrade и поведение переустановки сначала проверить. Обновление Pi не заменяет обновление IPK. Оболочка должна переживать несовместимую версию API: локальный экран сообщает о необходимости обновления и сохраняет доступ к настройкам.

## Пульт, фокус и Back

Стрелки и OK должны полностью покрывать настройку адреса, каталог, диалоги и управление плеером; Magic Remote pointer — дополнительный способ. Видимый фокус обязателен, восстановление фокуса — после закрытия модального окна/возврата из плеера. Не добавлять второй глобальный обработчик поверх Lampa: адаптировать существующую цепочку клавиатуры.

Back закрывает верхний диалог, затем возвращает по истории; на корне передаётся платформе согласно официальным рекомендациям. Поведение `webOS.platformBack()` и appinfo-параметров следует проверить на устройстве. Удержание клавиш, повторы, экранная клавиатура, переключение pointer/5-way и Back во время загрузки входят в ручную проверку. Нельзя навсегда блокировать системный выход.

## Движок, сеть и воспроизведение

Одинаковый webOS marketing version не является доказательством поддержки современного JS. До выбора transpilation target получить модель, firmware, webOS/SDK version и user agent, сверить официальную таблицу движков. Старый WebKit требует отдельной проверки синтаксиса, Promise/fetch/URL, CSS и памяти; полифиллы добавлять по фактическим потребностям. Наличие встроенного браузера не гарантирует идентичное поведение packaged app.

Первый playback probe: короткий собственный MP4 с известными AVC/AAC, затем нужные пользователю контейнеры, HLS/DASH, диапазоны HTTP Range, перемотка, audio/subtitle tracks, pause/resume и длинный сеанс. Поддержка кодека зависит от модели, профиля, уровня, разрешения, bitrate, аудио и DRM. Pi не исправляет неподдерживаемый codec без отдельного транскодирования; Pi 4 не считать гарантированным realtime-транскодером. Торрент не является URL, который автоматически понимает HTML video: для такого сценария нужен отдельный источник HTTP-потока.

Проверить CORS для origin packaged app, HTTPS trust chain, часы TV, mixed content и редиректы на каждом сетевом узле. Не ставить wildcard CORS с credentials. Старые TV могут не доверять актуальному сертификату: сначала проверить цепочку и прошивку, затем выбрать совместимую цепочку/локальный сертификат с установленным доверием, если TV это поддерживает. Не отключать проверку TLS. HTTP допустим только как явно выбранный режим доверенной LAN с объяснением отсутствия шифрования; admin остаётся защищённым.

## Приёмка и неизвестные

Нужны физический TV и его модель/год/firmware; пока это блокер подтверждения установки, фокуса, TLS и playback. Минимальная приёмка: запуск с выключенным Pi; восстановление после возврата Pi без перезапуска; неверный адрес и DNS; TV reboot; Back и фокус; потеря сети в видео; обновление IPK с сохранением настроек; истечение Developer Mode в безопасном тесте; memory/performance на длительном сеансе. Симулятор и Web Inspector помогают с JS/DOM, но не заменяют аппаратные кодеки. Диагностический экран показывает версии и коды ошибок без токенов, cookies и полного приватного URL.
