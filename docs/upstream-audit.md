## Инициализация и контракт расширений

[index.html](https://github.com/yumata/lampa/blob/6fcdfab624f98ac0f7a91244e3d3b637f104a8c2/index.html) подключает webOSTV.js, jQuery, notify, scrollbar, navigator, keypad; загружает приложение посредством встроенного загрузчика. [src/app.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/app.js) содержит `initClass`, `startApp`, `loadTask`, `loadApp`: экспортирует `window.Lampa` с Storage, Favorite, Timeline, Account, Player, API и другими объектами. Это реальный публичный контракт плагинов; удаление экспорта Account целиком ломает совместимость.

`startApp` инициализирует Storage → Timeline → Mirrors, далее UI/Settings/Favorite, Socket → Account → Extensions → Plugins, Player/WebOSLauncher/AdManager и сервисы. `loadTask` открывает Cache DB, читает Storage reserve, запускает Mirrors.task → Plugins.task → VPN.task → Account.task, затем Plugins.load/showApp. Изменения политики должны действовать **до этих задач**, а не плагином, который загрузится после первых запросов.

В `window.lampa_settings` заданы socket_use/account_use/account_sync/plugins_use/plugins_store, services/geo/mirrors и disable_features. По умолчанию сетевые возможности включены. IPTV меняет часть флагов, но это отдельный продуктовый режим; не готовая политика удаления CUB. `account_use=false` запрещает учетную запись, но не блокирует все обращения CUB.

## Storage, настройки, закладки и прогресс

[src/core/storage/storage.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/core/storage/storage.js): `get/set/value/restore/keys`, RAM-кеш и localStorage; при quota предусмотрен IndexedDB reserve через Cache (`task`, `writeReserve`, `ready`). Экспорт только localStorage неполон: значения могли переехать в reserve. [src/utils/cache.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/utils/cache.js) обслуживает IndexedDB, в том числе кеш плагинов, storage и other. [src/core/storage/workers.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/core/storage/workers.js) содержит синхронизацию структур и Socket.send('storage'); Storage.init слушает отправку и вызывает API storage/update. Настройки: [src/interaction/settings/params.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/settings/params.js) (поля/значения/дефолты), [src/interaction/settings/settings.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/settings/settings.js) и [src/interaction/settings/api.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/settings/api.js) (UI и API расширения).

[src/core/favorite.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/core/favorite.js): `category = like,wath,book,history,look,viewed,scheduled,continued,thrown`; `read/full/save` используют `favorite` с `card: []` и массивами ID. При Permit.sync `add` отправляет событие вместо локального сохранения, `get/check` читают Account.Bookmarks. Поэтому существующий favorite не является гарантированной копией облачного состояния.

[src/core/account/bookmarks.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/core/account/bookmarks.js): очередь операций, dump/changelog, tracker `account_bookmarks_sync`, IndexedDB other/`account_bookmarks_<profile.id>`. `get(type)` возвращает data, `all()` теряет оболочку с type — нельзя использовать all() как единственный экспорт для миграции категорий. `sync()` отправляет локальный favorite **в CUB**, это не импорт облака в локальное хранилище.

[src/interaction/timeline.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/timeline.js): `filename()` = `file_view_<profile.id>` при Permit.sync, иначе `file_view`. `link/indexKey/buildIndex` связывают hash с card/season/episode; при смене названия записи сохраняют сопоставимость. [src/core/account/timeline.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/core/account/timeline.js): timeline/update, dump/changelog, tracker account_timeline_sync, профильный файл; исходный file_view может использоваться как начальная копия. Простое выключение sync переключает пространство ключей и визуально «теряет» профильный прогресс.

[src/core/account/backup.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/core/account/backup.js) использует Storage.keys/value/restore и сетевой backup; это не автономный механизм резервной копии без CUB. Локальная история Favorite.history и облачная watch_history — разные пути: [src/components/watch_history.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/components/watch_history.js), [src/core/account/api.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/core/account/api.js) (`watchHistory`, `watchHistoryCard`), [src/interaction/menu/menu.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/menu/menu.js). Потерю серверной истории нельзя исключить наличием локального favorite.

## Плагины и динамический код

[src/core/plugins.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/core/plugins.js): plugins в Storage, локальные URL и аккаунтные расширения; `addPluginParams` подставляет storage placeholders, email (Base64), logged, random reset, origin; `modify` переписывает cub.watch. `push/load` вставляют script; `updatePluginDB/createPluginDB` сохраняют и исполняют кешированный код. Код из IndexedDB остается исполняемым даже при недоступной сети. `loadBlackList` тоже использует сеть CUB. [src/interaction/extensions/extensions.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/extensions/extensions.js) и модули extensions предоставляют каталог/установку/настройки. [src/services/remote_configuration.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/services/remote_configuration.js) умеет через registration/accept устанавливать плагины, менять storage, перезагружать приложение.

[src/services/libs.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/services/libs.js) загружает hls/dash/qrcode локально либо с github_lampa для file:/extension, а также CUB /plugin/sport, tsarea, shots, engineer. Флаг services закрывает только sport/tsarea; shots/engineer имеют самостоятельные условия. [src/services/events.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/services/events.js) подгружает /plugin/<event>; [src/core/iptv.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/core/iptv.js) — /plugin/iptv.

## Плеер и webOS

[src/interaction/player/video/webos.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/player/video/webos.js): `start` выбирается для Platform.is('webos'), создает WebOSParser, прокидывает webos_tracks/webos_subs для совместимости, управляет аудио/субтитрами, speed/rewinded/destroy. [src/interaction/player/video/webos/parser.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/player/video/webos/parser.js) содержит отдельную платформенную работу с media metadata. [src/interaction/webos_launcher.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/webos_launcher.js) использует `webOS.fetchAppId` и `luna://com.webos.service.eim` для launcher у вручную установленных виджетов. ## Сборка, зависимости и лицензии

[gulpfile.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/gulpfile.js): Rollup entry src/app.js, IIFE, Babel preset-env/commonjs/node-resolve/web-worker-loader, Sass/autoprefixer, сборка языков/плагинов; `pack_webos`, `pack_tizen`, `pack_github`, write_manifest. `merge` подавляет Rollup warnings и глобальный uncaughtException handler лишь печатает ошибку — exit status требует проверки артефактов. `npm start` запускает gulp watcher/browser-sync, не отдельный production HTTP сервер.

[package.json](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/package.json): npm start/debug/test/doc, vitest ^0.32.4; Rollup ~2.58.0, Babel ^7.15.8, gulp ^4, Sass ^1.43.4, browser-sync, redis, subsrt, regenerator и прочие зависимости. Lockfile в проверенных деревьях не найден: semver ranges не фиксируют транзитивный граф. Vendor JS — отдельные распространяемые артефакты, не весь runtime описан package.json. Есть spec для storage reserve, account backup/bookmarks/timeline, player tracks, Tizen lifecycle, watch history и parser; тесты в рамках аудита не запускались.

**Лицензионный конфликт — обязательный gate перед распространением.** [LICENSE](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/LICENSE) и [LICENSE](https://github.com/yumata/lampa/blob/6fcdfab624f98ac0f7a91244e3d3b637f104a8c2/LICENSE) содержат GNU GPL v2, тогда как package.json заявляет ISC. Нельзя выбирать ISC по удобству или объявлять весь vendor-код GPL. Нужно зафиксировать происхождение, выяснить применимую лицензию у правообладателя, сохранить уведомления и предоставить соответствующие исходники/изменения согласно установленным условиям. [webos/LICENSE-2.0.txt](https://github.com/yumata/lampa/blob/6fcdfab624f98ac0f7a91244e3d3b637f104a8c2/webos/LICENSE-2.0.txt) содержит отдельную лицензию SDK; vendor, шрифты, изображения и динамические плагины требуют самостоятельной инвентаризации. Полный SBOM и юридическое заключение этим исследованием не получены.

## Границы доказательства

Подтверждены пути, условия и вызовы в зафиксированных исходниках и структура published build. Не проверены живые ответы серверов, DNS/CNAME, редиректы, поведение конкретного webOS, все ветви bundle и загруженный при исполнении сторонний код. Полнота zero-CUB не следует из grep: динамические плагины, пользовательские зеркала, конкатенация URL и кеш требуют ограниченного списка допущенных расширений и runtime сетевого теста. Карта и предлагаемые изменения: [cub-removal.md](cub-removal.md).


## Изменения 3.x и стратегия совместимости

[UPGRADE.md](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/UPGRADE.md) описывает переход 2.4.7→3.0.0; это проверено по текущему коду, а не принято как самостоятельное доказательство. `src/app.js` импортирует и экспортирует `Maker` и `Router` (строки 108/112/363/367). [interaction/maker.js](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/maker.js) регистрирует классы Card/Main/Category/Line и их Module/Map; `interaction/constructor.js` и `utils/mask.js` обеспечивают композицию модулей. Существуют отдельные `interaction/card/module/map.js`, `interaction/items/main/module/map.js`, `interaction/episode/module/map.js`. `src/core/router.js` — отдельная точка маршрутизации. Следовательно, legacy monkey-patch старого `Lampa.Card` не охватывает все новые карточки; интеграционные тесты нужны для обоих путей.

Руководство объявляет устаревшими Card/InteractionMain/InteractionCategory/InteractionLine и переводит presentation flags на `params`, `module`, `emit`, `createInstance`. Их не следует сериализовать как произвольные функции в Config API. Provider возвращает данные, compatibility bridge создаёт runtime presentation params. Проверка `Manifest.app_digital >= 300` — upstream shortcut, не полноценный semver comparator; Home использует отдельное сравнение версий контрактов.
