# ИИ-подборки

Администратор включает функцию и задаёт ключ OpenAI в настройках сервера. Ключ остаётся на сервере. Клиент использует существующий идентификатор устройства и передаёт нормализованные сигналы избранного и прогресса; исходные ссылки на потоки и торрент-файлы не передаются. Устройства сохраняют собственные снимки, а профиль выбирает сервер.

В админ-панели можно отдельно изменить промпты главной и похожих подборок (до 4000 символов каждый). Они применяются к новым генерациям; существующие карточки обновляются при явном обновлении подборки. Для главной сервер передаёт OpenAI явные лайки с названием и годом. Модель ищет идеи через web_search и предлагает названия, годы, объяснения и источники; сервер ищет предложенные названия через TMDB и собирает карточки из проверенных результатов. История используется на сервере для исключения просмотренного. Сохранённые пользовательские промпты при обновлении не перезаписываются. Чтобы применить текущий промпт по умолчанию с поиском в интернете, используйте кнопку восстановления: она подставляет серверное значение только в форму; для применения нажмите «Сохранить настройки ИИ». Сам сброс не запускает проверку подключения или генерацию.

Источники сверяются с URL завершённого поиска и его цитатами. При сравнении игнорируются параметры отслеживания `utm_*`, `gclid`, `fbclid`, `msclkid`, `yclid`, `dclid`; остальные параметры, фрагмент и адрес страницы сохраняют значение. В результат попадает исходный URL провайдера. Неподтверждённые ссылки удаляются, а название продолжает проверку в TMDB с предупреждением о качестве источников.

После включения на главной показывается кэшированный ряд «Для тебя». В настройках «ИИ-подборки» доступно ручное обновление и состояние синхронизации. Получение кэша не запускает генерацию. Кнопка «ИИ-подборка» в карточке фильма или сериала открывает подборку по выбранному произведению. При отсутствии кэша это явное действие создаёт задачу; выход с экрана не отменяет общую задачу сервера.

Снимок ограничен 1000 записями и 192 КиБ. Превышение не обрезает историю: загрузка отклоняется, предыдущий снимок сохраняется. В состоянии отображается число пропущенных неоднозначных записей. Серверные лимиты и расписание настраиваются администратором. Реальные затраты и задержка зависят от модели и ответа провайдера; измерения с настоящим ключом и проверка на физическом телевизоре пока не проводились.

Изменение одного времени последнего прогресса не вызывает новую передачу: время обновляется вместе с новым смысловым состоянием или изменением порядка истории. Полный отправленный снимок сохраняет проверяемый сервером digest.

## Обновление Pi и откат

До обновления сделайте согласованную резервную копию SQLite через SQLite backup API работающего старого контейнера и проверьте возможность её открытия. Текущая версия схемы базы — 5; это изменение не добавляет миграцию. При восстановлении из резервной копии данные возвращаются на момент её создания.

Используйте существующие Compose-файлы и те же локальные overrides домена, которые применяются на Pi; пересоберите и запустите сервис обычной командой проекта `docker compose ... up -d --build` с соответствующими `-f` файлами. Проверьте состояние контейнера и админ-панель после запуска. Не добавляйте ключ OpenAI в клиент или Compose: введите его только в админ-панели сервера.

Проверка с реальным OpenAI выполняется только после ввода ключа и явного действия администратора; она расходует настроенный бюджет запросов. Автоматические тесты используют фиктивные ответы и не подтверждают работу провайдера или управление пультом на физическом телевизоре. Отдельно проверьте там навигацию, возврат назад во время задачи и продолжение воспроизведения.


## Реализация и проверенные пределы

История начала торрента не считается досмотром. Лайки, закладки/позже, начатое, просмотренное и брошенное учитываются отдельно. Старый прогресс без надёжного provider не присоединяется к случайно совпавшему TMDB ID; новые checkpoints сохраняют source. В интерфейсе есть отчёт пропущенных записей. Начальное объединение — профиль home, но снимки разделены по устройствам для дальнейшего назначения индивидуальных профилей.

Рекомендуемые по умолчанию лимиты: 12 карточек, один автоматический home-job в сутки по московскому времени, максимум 8 исходящих попыток на профиль и 32 на сервер. Включённый из расписания catch-up не запускает вторую автоматическую генерацию в тот же день. Все внешние attempts учитываются, включая retry и неопределённый результат timeout. Истёкшая same-title подборка обновляется по явной кнопке, работающая задача продолжается без дублирования.

Метаданные кэшируются 24 часа в памяти процесса; повторные jobs используют один catalog для текущего endpoint/revision. Пул ограничен тремя catalog instances и очищается при перезапуске; ai_metadata_cache зарезервирована миграцией, но persistent metadata cache в этом этапе не подключён. Готовые подборки, jobs, снимки, квоты и idempotency aliases сохраняются в SQLite.

Подписи языков торрента перечисляют реальные дорожки. Все дорожки и раздачи сохраняются; подтверждённые RUS Дубляж и RUS показываются первыми, русские субтитры не считаются русской озвучкой. Неопределённый язык обозначается отдельно. Автоматический выбор аудио в плеере не меняется. Ручное обновление Lampa Home сообщает начало, применение, отсутствие изменений или ошибку; фоновое обновление остаётся тихим.

Просмотренный фильм не возвращается в выдачу, но может быть основой похожих рекомендаций. Для генерации главной нужны явные лайки; история и закладки сами по себе их не заменяют. При отсутствии лайков интерфейс предлагает добавить их. Досмотр сам по себе не превращается в лайк.

Запросы и ответы новых вызовов ИИ, включая промпты и переданный модели контекст, сохраняются в административных трассах до 14 дней: максимум 200 трасс и 64 МиБ. Заголовки авторизации и ключи не сохраняются. Администратор может открыть трассу и явно запустить платное сравнение с другой моделью; это не изменяет карточки главной. Доступ к панели следует предоставлять только доверенным администраторам.

Аудит ранее загруженного запроса показал три лайка, 120 кандидатов и размер около 151 КБ. Новый запрос передаёт компактный контекст лайков и использует поиск; MCP отложен и для этой версии не требуется. Реальная работа нового потока с провайдером ещё не проверялась.

Поиск источников обязателен: ответ должен содержать завершённый web search; если провайдер не вернул URL, ссылки могут отсутствовать. Для каждого предложенного названия сохраняются только URL, совпавшие с источником или аннотацией провайдера (известные tracking-параметры игнорируются). Несовпавшие URL удаляются. `citationStatus` равен `verified`, если все заявленные ссылки подтверждены, `partial`, если подтверждена часть, и `unverified`, если подтверждённых ссылок нет, в том числе для пустого массива. Отсутствие подтверждённой ссылки не отклоняет название: оно всё равно проходит строгую проверку названия, года и типа в каталоге TMDB. В provenance и диагностике `citationSummary` содержит количество предложений каждого статуса; старые события могут не содержать это поле. Диагностическая трасса по-прежнему хранит исходный ответ провайдера.
