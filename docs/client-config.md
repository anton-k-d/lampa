# Настройки Pi в WEB/MSX-клиенте

Клиент `/app/` читает `GET /v1/devices/{id}/client-config` с того же сервера. В настройках клиента есть раздел **Lampa Home**: ID устройства, состояние загрузки, адреса подключений и кнопка обновления. Для первой установки нового кода нужно пересобрать Docker-образ и заново открыть Lampa в MSX.

В админке задайте:

- TMDB Proxy: базовый URL самописного Express proxy. Предоставленный пользователем `app.js` подтверждает `/3/...` для API и `/image/...` для изображений, TMDB API key подставляется удалённым сервером. Из ссылки `/tmdb-proxy.js` выделяется базовый URL, JS-плагин не загружается. Поле ключа TMDB этому контракту не требуется и отмечается как неприменяемое, если заполнено.
- Jackett: базовый URL, API key и явное включение службы.
- TorrServer: базовый URL и явное включение. Сейчас управляемое подключение работает без авторизации. Старый локальный Basic login/password не отправляется новому управляемому адресу. Credential references для управляемого TorrServer пока отклоняются клиентской проекцией.

Обновление выполняется при старте, раз в 30 секунд в активной вкладке, при возвращении на экран и по кнопке. Оно не перезагружает интерфейс и не останавливает плеер: текущее видео продолжает использовать свой URL. Назначенный TMDB также выбирает native источник tmdb поверх прежнего локального выбора CUB. Управляемые поля имеют приоритет и доступны локально только для чтения. Их исходные локальные значения не перезаписываются. Удаление назначения восстанавливает локальное поведение; явное выключение не включает старый локальный адрес.

При ошибке API сохраняется последняя корректная конфигурация, ожидание старта ограничено 2,5 секундами. Если недоступен весь Pi, MSX не сможет загрузить сами HTML/JS: это не packaged offline-приложение. ID и кэш хранятся отдельно от native Storage в localStorage текущего origin. IP вместо `lampa.pi` или другой порт — отдельное браузерное хранилище. ID из Home можно использовать для индивидуальных настроек в админке.

По явному решению пользователя от 2026-11-10 LAN-клиент получает выбранный **Jackett API key**, в том числе в last-known-good кэше. Это заменяет прежнее требование backend-only credentials для этого прототипа. Endpoint отдаёт только ключ эффективного Jackett, не весь реестр секретов; использует no-store и не открывает CORS. Ключ не показывается в Home и не попадает в административный JSON-экспорт. Штатный прямой Jackett использует key в URL запроса. Прототип по-прежнему не имеет авторизации.

Поддерживаются metadata.locale → tmdb_lang и ui.animations → animation. Для theme/density нет точного native соответствия: Home показывает их как неприменяемые. Полное удаление CUB и реальные Pi/TV playback-проверки остаются следующими этапами.

Предоставленный TMDB Proxy логирует свой TMDB_API_KEY в pathRewrite/onProxyReq. В его дальнейшей доработке нужны редактирование логов, фиксированные зависимости и тесты ошибок, timeout и целостности streaming response. Его код этим изменением не модифицируется.
