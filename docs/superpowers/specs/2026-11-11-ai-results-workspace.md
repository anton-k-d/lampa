# AI history, RAW and TMDB cards

User requests a designed admin interface and parallel economical implementation: history as exact RAW and Lampa-like TMDB card results, plus why each title was selected. Existing reason already comes from the model; expose it clearly and strengthen its personalization without an additional paid explanation call.

## Interface
Keep full-width responsive admin and existing history, quota/copy/compare controls. Selected-event workspace has two panels: original and selected comparison. Shared Cards/RAW tabs. Cards show poster, title/year/type/rating, explicitly labelled model explanation and optional description, citation warning and outcome. Filters separate included, excluded and unresolved; comparisons/reconstructed previews use resolved (not published) status. Source/time/model/counts and pipeline errors remain visible. RAW content remains exactly stored text with copy; no pretty-print replacement. History of direct child comparisons can be selected without rerunning a model. OpenAI replay is the only paid action and remains explicit.

Snapshot historical result metadata at execution time; viewing a history record must not resolve against today's favorites or trigger model/proxy searches. Posters may load from configured proxy, with local placeholder on failure. Older records say result unavailable; explicit POST preview resolves stored RAW through TMDB only and is labelled reconstructed/current metadata. Never pass reconstructed results off as historical or publish comparison previews to Lampa.

## API contract
Existing GET /v1/admin/diagnostics/ai/{id} adds result:null|snapshot and preview:null|snapshot, existing event/trace/parentEventId unchanged. GET .../ai/{id}/comparisons?limit=&beforeId= returns paginated {items:[event metadata],nextCursor}. POST .../ai/{id}/preview {} returns {eventId,result:snapshot}; this result is the reconstructed preview, stored separately from immutable generation result. No OpenAI attempt or job/cache publication for preview.

Snapshot shape: {schemaVersion:1,mode:generation|comparison|reconstructed,state:pending|ready|failed,capturedAt,context:{kind,anchor:null|{title,original_title,year,media_type}},selection:null|existing counters,errorCode:null|string,items:[{status:included|excluded|resolved|unresolved,proposal:{title,original_title,year,media_type},card:null|nativeNormalizedTMDBCard,posterUrl:null|string,reason:string,sources:[verifiedURL],citationStatus:verified|partial|unverified,exclusionCode:null|WATCHED|LIKED|SEED|DUPLICATE|ADULT|NOT_FOUND|AMBIGUOUS|METADATA_ERROR}]}.

Generation snapshots include all model proposals and exact exclusion outcomes at that time. Comparison and reconstruction previews do not apply/publish profile filtering: resolved means metadata found, not added to a TV. Ready means preview available, not necessarily generation publication. Generation failures can retain snapshot items and errorCode. Legacy unsupported/raw-redacted/truncated data must fail clearly without fabricating cards.

## Storage and transport
Use existing diagnostic_ai_traces snapshot_json to hold optional result and preview beside unchanged raw trace fields; getAI splits extras to top level, trace remains null if no actual request capture. Result-only snapshots are allowed without invented raw request/response. Existing14day/200trace/64MiB budget covers snapshots too; cap each structured snapshot256KiB, max12 items. No database migration/dependency/new service. Known secrets redacted in content; identifiers/statuses immutable and URLs validated. Final original result must not be overwritten by reconstruction. Existing event IDs/timestamps/usage/paid counters unchanged.

Extract pure parseResearchResponse(response) from research to reuse validation for stored responses and comparisons without another model call; synthesize SDK output_text from raw output blocks when parsing stored HTTP JSON. Normal generation captures its exact catalog matching/filtering result; replay stores independent resolved comparison snapshot after the existing paid request. Proxy failure in preview does not convert a successful model call into a provider failure or trigger paid retry. Explicit preview is bounded/singleflight per event and does not mutate generation results/jobs/batches/quotas. Catalog imageUrl helper uses configured TMDB Proxy /image/t/p/w342/{poster}, validates relative image path and never uses CUB/public fallback.

## Safety and acceptance
Strict TMDB identity matching and current citation policy unchanged. Fixed safe labels and textContent, no HTML interpolation or untrusted image/link protocols. GET/detail/history/cards are read-only; preview only TMDB, paid replay one existing budgeted call. Test snapshot persistence after profile/config changes/restart, retention and secrets, result-only/legacy records, comparison history, zero paid requests on reading/previewing/copying, partial/unmatched/excluded states, raw exactness, stale response guards, mobile/desktop layout and image failure. No live provider key or remote proxy available in cloud; use real local HTTP/SDK fixtures. Publish after verification as authorized in session.
