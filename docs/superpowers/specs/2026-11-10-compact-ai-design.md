# Compact AI internet research

## Evidence and final user direction
Uploaded API request parsed locally: three taste entries, all liked; three matching seed cards; 120 generated candidate cards; serialized JSON about 151KB. Extra titles were server candidates, not extra user favorites. User now explicitly simplifies: no MCP, only internet research. This supersedes the earlier remote MCP design. Latest instruction prohibits publication/push/deploy.

## Design
Replace normal home/similar candidate ranking with one Responses request containing compact liked titles (title, original_title, year, media_type), optional explicit similar title, locale and saved prompt. Hydrate at most40 explicit liked records; no bookmark/planned/history fallback. Do not send liked IDs, descriptions, posters, candidate IDs or watch history. Home without likes returns no_likes before provider spend; explicit similar works without likes. History, started/completed/abandoned records remain local to exclude watched output; likes and explicitseed are excluded from suggestions.

The model uses hosted web_search only, researching reviews, genre connections and thematic recommendations, then returns structured title/original_title/year/media_type/reason/source_urls proposals, at most12. max_tool_calls3/max_output_tokens2500/storefalse, modelgpt-4.1-mini and existing quota reservation/no SDK retries. Require actual successful web search and sources, not merely a model claim. Reject citations not present in actual tool search sources/annotations, refusals/incomplete/invalid data; propagate raw trace/known usage for paid errors. No MCP setting, dependency, server, connection, config field, tool or fallback.

After paid generation, backend searches title+year+type through existing TMDB Proxy, matches normalized original/localized title and year uniquely, hydrates verified cards and rechecks identity. Never choose first result/popularity or invent IDs. Unresolved/ambiguous suggestions skipped with explicit server result; no cards means safe jobfailure and oldcache retained. This resolver is independent of OpenAI: metadata failures after paid success must not cause a second AI call. Keep model reasons/sources in API/cache. Metadata credentials remain on existing proxy.

Keep raw exchange/error/usage journal and replay; replay permits strictly bounded stored web_search payloads only and changes just model. Existing quotas/CAS/idempotency/signal sync unchanged. Version newcache/provenance to web-research-v2 and mark old pipeline cache stale; preserve prior cards offline/error. Preserve user custom prompts, change standard prompts to internet/explicitlikes. Existing connection test remains simple OpenAI probe and does not assert web-search readiness.
