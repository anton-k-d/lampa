# Client configuration bridge

The next increment connects the same-origin MSX/WEB client to the existing Pi configuration. The user explicitly permits client-side connection keys for this trusted LAN prototype (2026-11-10), superseding the earlier requirement to keep every connector key on Pi. Only the selected Jackett key is delivered; unrelated runtime secrets remain private. No authentication or cross-origin administrative access is added. Do not log keys or add them to admin exports.

Add GET `/v1/devices/{id}/client-config`: a versioned, whitelisted projection of one consistent effective snapshot, with revisions and ETag/304. Apply the existing schema, runtime policy and Lite validation. Resolve only the credentialRef selected by that device's effective Jackett endpoint. Response and browser cache contain the selected key by explicit user choice; send no-store. Preserve the existing generic effective endpoint unchanged. Distinguish explicit global/device assignments from defaults so an empty server configuration preserves all local connections.

The client's stable schema-safe device ID and last-known-good snapshot use namespaced local storage. Load a validated cache immediately, fetch with a bounded startup timeout, and always continue initialization. Read from the current origin only for HTTP(S) WEB/MSX. Poll with ETag and refresh on foreground, with one request in flight. Invalid/offline responses retain the previous snapshot. No reload or player stop on refresh. Expose device ID, connection status and effective URLs in a small native Home settings section; never display the key there.

Managed values form a runtime overlay, not `Storage.set` migration: existing native settings remain intact and resume when a server assignment is removed. Map managed Jackett to parser_use, parser_torrent_type=jackett, jackett_url/key and primary selection; suppress stale local secondary connections while primary is managed. Map TorrServer primary/backup, enabled, preload/saveToDatabase without discarding existing auth settings. A managed disabled TorrServer must not fall back to old local URLs. Authenticated managed TorrServer is outside this increment unless its real credential representation is already supported.

The supplied TMDB proxy source establishes `/3/{relative TMDB API path}` and `/image/{image path}`, with the API key replaced remotely. Use its configured base URL directly and preserve path/query semantics; never load `/tmdb-proxy.js`. Managed metadata must win over the upstream automatic TMDB proxy/geo setup, including when configuration changes after startup. Do not fall back to CUB on managed proxy failure. Metadata locale maps to tmdb_lang. Map animations to native animation. Theme/density have no exact native mapping: show them as unsupported rather than invent one. Full CUB removal remains a later increment.

Acceptance: save the three endpoints and Jackett key in admin, reload `/app/`, and observe actual TMDB/Jackett/TorrServer calls to configured fixture servers. Two devices receive independent overrides and stable IDs. Empty configuration preserves local values; removing managed fields restores them. Offline/invalid/timeout/304 preserve valid state, startup finishes, and refresh never reloads playback. Verify secrets are absent from status UI/logs/admin export and only the selected key is returned. Real Pi/TV playback is still manual acceptance.
