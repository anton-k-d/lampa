## Минимально инвазивная стратегия (предложение)

1. Сохранить оригинальные Storage/Favorite/Timeline/Player и интерфейсы window.Lampa. Добавить одну раннюю политику сборки без CUB: account_use/account_sync/socket_use/geo/mirrors выключены, CUB plugin store/remote config/metrics/ads не стартуют. Нужны точечные guards транспортных инициаторов из таблицы, а не только замена домена или CSS hide. Отключенная boot задача обязана вызвать callback, иначе зависнет загрузка.
2. До первого запуска новой политики сделать атомарный снимок через Storage API и IndexedDB: favorite, file_view, все file_view_<profile>, account_bookmarks_<profile> в other, account/profile, tracker keys, plugins, online/torrent/search state. Не логировать токены; хранить backup локально. Для смены origin/scheme/порта требуется явный export/import: браузер не переносит хранилище между origins.
3. Выбрать текущий профиль по account.profile.id и материализовать его закладки по каждому type из Bookmarks.get либо сырой cache/dump; восстановить favorite.card и массивы ID, сохранив порядок и типы. Объединять с существующим favorite по категории/источнику/ID; исходная схема использует числовые ID и допускает коллизии разных источников — конфликт нельзя молча разрешать потерей карточки. Архивировать исходные структуры. Не сливать детские/взрослые и разные профили автоматически: активный профиль в рабочее локальное состояние, остальные — в именованные локальные архивы/профили.
4. Слить file_view активного профиля с локальным file_view: при одинаковом hash выбирать запись с более свежим updated, сохраняя duration/time/percent/card/season/episode. Сохранить альтернативные конфликтные записи в backup. Не менять hash и `link` правила: источники tmdb/cub в upstream разделяют карточный namespace. При наличии различающихся hash учитывать привязку card/season/episode, не склеивать разные эпизоды. Миграция должна быть идемпотентной, с version marker **после успешного сохранения**, и rollback из снимка.
5. Серверная watch_history не гарантированно есть в кеше Bookmarks/history. Если нужен полный перенос облачной истории — отдельный предварительный экспорт при доступном аккаунте; без такого экспорта честно обозначать перенос как «локально доступные данные». Этот этап потребует отдельного разрешения на обращение к аккаунту; в текущем исследовании он не выполнялся.
6. После миграции отключить Permit.access/use/sync и cloud endpoints, сохранив безопасный Account facade: false для permissions/premium, пустые результаты и завершение callbacks/promises для API, пустые notices. ## Проверяемые критерии zero CUB (предложение приемки)

- Собранный index/bundle/css/lang/vendor/plugins не содержит активных CUB URL, startup registrations, auth/premium/ad widgets и callback-зависаний. Документы/лицензионные notices могут содержать исторические упоминания; это не запросы. Остатки допускаются только в явном inert allowlist с объяснением.
- Сетевая запись браузера **и** контроль на egress показывают ноль попыток DNS/HTTP(S)/WS к всем зеркалам выше, их поддоменам, пользовательским cub_mirrors, связанным redirects и CUB scripts. Проверять чистый профиль и мигрированный snapshot; затем DNS/network полностью заблокированы для CUB. Приложение должно стартовать и работать с локальными данными.
- Набор сценариев: холодный/повторный запуск; минимум 16 минут для mirror timer и reconnect; настройки, поиск, карточка, аниме, empty state, актер, продолжение, история, избранное, плеер start/pause/seek/end/reopen, субтитры/аудио webOS, theme/screensaver, языки, ошибки сети, extensions/settings, старый кеш plugins. Отдельно несколько профилей, quota reserve, отсутствующий IndexedDB, file:/HTTP/HTTPS и реальный целевой webOS. Факт статического аудита не заменяет эти испытания.
- После миграции число карточек/категорий, их порядок и выбранные записи history сверяются с экспортом; progress round-trip сохраняет значения/metadata. Повторная миграция не дублирует записи. Новые локальные favorite/history/progress переживают reload и отключенную сеть; rollback восстанавливает snapshot. Облачные данные, которых нет в снимке, явно перечислены как неперенесенные.
- Выполнить релевантные upstream spec (storage_reserve, account_bookmarks_parse, account_timeline, watch_history_info, player_track_info и платформенные lifecycle) и отдельные meaningful migration tests. В этом исследовании тесты не запускались и критерии не объявляются пройденными.
- Зафиксировать точный список разрешенных plugins и их хеши. Для произвольного будущего URL-плагина гарантия не распространяется автоматически; его нужно проверить до разрешения исполнения. Итоговое утверждение ограничивать конкретной сборкой, конфигурацией, моделью TV и набором расширений.
